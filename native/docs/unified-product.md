# Unified native product and release gaps

The intended product uses `com.justinharbour.simpledocs` for the main app on iOS/iPadOS, macOS and eventually tvOS. The current project builds iOS/iPadOS and macOS. The selector offers the existing self-hosted instance or a direct Telnyx connection. Direct mode stores a user-supplied key in the device-only, non-synchronizing Keychain and explicitly fetches only the first page of Telnyx fax records. It does not send, retrieve documents, list PostGrid records, handle calls or voicemail, synchronize, capture inbound traffic, or register push. The provider key is transmitted to Telnyx only on explicit fetch; redirects are refused. A separate macOS synthetic preview is not shipped. Switching modes does not delete the connected session or the key. The existing Keychain service name is not itself an entitlement and does not guarantee access across changed app identities. Additional direct actions require real adapters, eligibility, data-flow review and appropriate confirmations.

Apple's [App Store Connect documentation](https://developer.apple.com/help/app-store-connect/create-an-app-record/add-platforms/) supports adding macOS and tvOS to an iOS record with the same bundle ID, SKU and Apple ID. Platform builds and metadata remain platform-specific; this does not imply one binary. tvOS requires its own target, remote/focus UX, authentication and tests. The SDK supports `ASWebAuthenticationSession` on tvOS 16+, but presentation, ephemeral-session and cancellation APIs differ from iOS; the existing authentication flow is not yet adapted. [UserNotifications](https://developer.apple.com/documentation/usernotifications) supports tvOS, but the current Worker only accepts iOS/macOS push registrations, and there is no tvOS call or notification display. No tvOS target is claimed.

Apple's [extension table](https://developer.apple.com/documentation/technologyoverviews/app-extensions) lists Share extensions on iOS/iPadOS and macOS, not tvOS. Each platform's extension `com.justinharbour.simpledocs.share` writes one size-limited PDF per invocation to its local `group.com.justinharbour.simpledocs` shared container; iOS uses complete file protection and macOS uses a sandboxed container. The connected Send screen lists queued PDFs for explicit add and manual deletion; files remain until deleted, and no request is sent by the extension. Direct mode cannot yet consume the inbox. This requires owner registration of the App Group and extension ID, matching entitlements and signed profiles, and real-device testing of sharing, file protection and cleanup. No Keychain sharing is enabled.

Apple's [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) require data security (1.6), extension compliance (4.4), and transparency and permission for applicable data sharing (5.1). Apple's [2026 App Store Connect lab](https://developer.apple.com/videos/play/wwdc2026/8010/?time=1553) discusses user-supplied third-party keys and privacy, not a blanket approval of any implementation. Review provider terms and current guidelines, submit complete review access, and obtain Apple review for the actual app; no general approval is claimed. Do not embed developer-owned secret keys in app binaries.

Before release the owner must verify ownership and availability of the main App ID, configure the platform records, capabilities, signing and provisioning, and test actual signed platform builds. This change makes no Apple account changes. Bundle ID changes mean separate installs and may isolate preferences and Keychain data. Confirm OAuth callback allowlists and deploy the compatible Worker and database migration first; see [self-hosted instances](self-hosted-instances.md) and [push](push.md). Preserve old callback and APNs topic support during migration, validate real device registration separately, and do not claim a live cutover from unsigned builds.
